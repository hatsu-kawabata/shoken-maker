分母（クロール量）を増やす前に歩留まりを上げるのが順序として正しい。

## 問題の定式化

現在の駅ページは **情報** であって **計算** ではない。

- 本文は約825字。うち可変部分は e-Stat の数字の転記のみ
- 1,992枚が互いに同型。タイトルも `◯◯駅の商圏人口・年齢構成（半径500m/1km/3km）` で完全に同じ鋳型
- したがって、任意の1枚は「他の1枚」でも「汎用LLMの回答」でも置換可能

「クロール済み - インデックス未登録」は、この置換可能性に対するGoogleの判定と読むのが最も素直である。
これは `~/moat/` の結論（**モートは情報でなく計算**）と同じ形の問題であり、同じ解き方が効くはずだ。

## 操作的証人（テスト可能な合格条件）

抽象を入れる代わりに、判定できる述語を置く。

```
distinctive(page) ⇔ page の本文に、コーパス全体を持たないと書けない文が1つ以上ある
```

実装上の担保（テストで機械的に検証する）:

1. 特徴文はコーパス統計（順位・パーセンタイル・中央値からの乖離・近隣比較）**のみ**から導出される純関数で生成する
2. 全ページの特徴文セットが**互いに一意**であること
3. 特徴文に含まれる数値が、集計値から再計算して一致すること（事実性）

**プロトタイプ実測（2026-07-29）**: 順位・中央値乖離・上下5%判定の3種だけで
**1,992駅すべての特徴文セットが一意（完全一致 0 件）**。原理的に足りることは確認済み。

## 施策

### 1. 特徴文の追加（主施策）

各ページに、コーパス全体からしか出せない文を置く。生成例（実データ）:

```
■ 熱海駅
  半径1km圏の人口は全国1,992駅中 第1,962位（下位2%）。
  平均年齢は全国中央値より13.2歳高い（58.6歳 / 中央値45.4歳）＝高齢層に厚い商圏。
  65歳以上比率は全国上位5%（第2位・45.6%）。

■ 那覇空港駅
  平均年齢は全国中央値より16.1歳低い（29.3歳 / 中央値45.4歳）＝若年層に厚い商圏。
  65歳以上比率は全国下位5%（第1,992位・2.0%）＝現役世代が集中。
```

分布の広がりは十分ある（1km人口 24〜88,994人 / 平均年齢 29.3〜58.6歳 / 65歳以上 2.0〜46.1%）。

**文言の注意**: 降順の順位をそのまま「上位X%」と書かない。順位が大きい側は「下位Y%」と言い換える
（プロトタイプはここを取り違えて熱海を「上位98%」と出した。純関数側で分岐させ、テストで両側を固定する）。

### 2. タイトル・見出しの分化

現在は全ページ同一鋳型。特徴が立つ駅では title に含める:

`熱海駅の商圏人口・年齢構成 — 65歳以上45.6%（全国2位）| 商圏メーカー`

閾値に達しない駅は現行のままにする（無理に差をつけると事実性が落ちる）。

### 3. 昼間人口の追加 →【訂正】従業者数で代替（2026-07-29 実測）

プロトタイプで **新宿駅の1km常住人口が全国1,334位** と出た。これは誤りではなく、
常住（夜間）人口だけを見ているためで、出店判断としては明確に不十分である。

**しかし昼間人口は地域メッシュ統計に存在しない。** 定義書で実測した結果:

| statsId | 実体 | 判定 |
|---|---|---|
| T001143（国調2020 別表02, 1km, JGD2011） | 「従業地・通学地」節はあるが、項目は**当地に常住する**15歳以上就業者・通学者 | ✗ 居住地ベース。通勤してくる人ではない |
| T001146/147（roadmapが「昼間人口プロキシ候補」としていた） | 実体は**令和3年経済センサス-活動調査 産業別事業所数・従業者数**（T001147はJGD2000） | ✗ 国勢調査ですらない |

昼間人口は市区町村・小地域には存在するが、メッシュには無い。したがって代替として
**経済センサスの従業者数**（T001163001 = Ａ〜Ｓ全産業、JGD2011・500m）を使う。
これは「そこに勤め先がある人の数」で、買い物客・通学者・観光客を含まないため
昼間人口の全部ではない。**ページでは昼間人口と呼ばず「そこで働く人」と書く。**

検算（2026-07-29）: 全国合計 62,427,891人。公表の民営従業者数 約5,795万人との差
約450万人は国・地方公共団体分（001は公務を含む）。同じ読み方で
T001163002（Ｃ〜Ｅ第２次産業）= 12,561,357人 も公表値と整合したので列の当て方は正しい。

結果（実測）: 新宿駅は「働く人が住む人の**15.82倍**（全国中央値0.43倍・第37位）」、
東京駅は99.87倍。祖師ヶ谷大蔵は0.22倍。狙いどおり常住人口だけでは見えない軸になった。

### 4. ハブページ

ランキングは単独で索引価値がある（検索需要のある語に対して、実データで答えられる）:

- 全国の駅 1km人口ランキング
- 65歳以上比率ランキング（高い順・低い順）
- 都道府県別の駅一覧

現状は `/pages/eki/` の平坦な一覧しかない。

## 裾（薄い駅）の扱い — 決めること

競合チェッカーでは「事業所100未満の3,928駅をスキップ」で薄さを回避した。同じ手を商圏メーカーにも当てるかは自明でない:

- 1km人口が極端に小さい駅（空港第2ビル24人・ベイサイド57人・那覇空港743人）は「商圏」の意味自体が違う
- 一方で熱海・軽井沢のような駅は、人口が小さいからこそ **特徴が際立つ**＝足切りは情報を捨てる

**推奨**: 人口での足切りはせず、計算不能（1km人口0）だけを除外する現行条件を維持し、薄さは施策1〜3で解く。
足切りは「特徴文が1本も立たない駅」＝ distinctive(page) が偽の駅に限る。これなら基準が操作的で、
実装とテストが一致する。

  観測日はクロール日基準で置く

## 実装順（根拠: 効果×コスト比）

1. **施策1（特徴文）+ 2（タイトル）** — 純関数＋テスト。既存パイプラインに載るので当日中に通る
2. **施策4（ハブページ）** — 生成器の追加のみ。新規データ不要
3. **施策3（昼間人口）** — 新規 statsId の特定とビルドが要る。roadmap フェーズ2と合流

英語面（`/en/eki/`）は順位も数値も言語非依存なので、同じ純関数をそのまま流用できる。
